# Provenance Guard

A backend that a creative-writing platform can plug into to estimate whether submitted text was
written by a person or generated by AI. It returns a confidence score that's honest about
uncertainty, shows readers a plain-language transparency label, lets creators appeal, and keeps
an append-only audit log of every decision.

AI201 Project 4. The design spec is in [`planning.md`](planning.md), written before the code.

---

## Quick start

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # then put your Groq key in .env
python app.py                      # http://localhost:5000
```

```bash
# Submit
curl -s -X POST http://localhost:5000/submit -H "Content-Type: application/json" \
  -d '{"text": "The sun dipped below the horizon, painting the sky in hues of amber and rose. I sat on the porch steps with my coffee going cold.", "creator_id": "test-user-1"}'

# Appeal (use the content_id from the submit response)
curl -s -X POST http://localhost:5000/appeal -H "Content-Type: application/json" \
  -d '{"content_id": "PASTE-CONTENT-ID-HERE", "creator_reasoning": "I wrote this myself from personal experience."}'

curl -s http://localhost:5000/log        # audit log
curl -s http://localhost:5000/appeals    # human review queue
```

Tests (no API key needed; the LLM is mocked): `python tests/test_app.py`

## Architecture overview

```
POST /submit {text, creator_id}
   │
   ▼
Rate limiter (10/min, 100/day per IP) ──429──▶
   │
   ▼
Validation (20–10,000 chars) ──400──▶
   │ raw text
   ├──────────────────────────────┐
   ▼                              ▼
Signal 1: LLM judge (Groq)     Signal 2: Stylometry (pure Python)
   │ llm_score 0–1 / null         │ stylometric_score 0–1 + metrics
   └──────────────┬───────────────┘
                  ▼
Confidence scorer: 0.6/0.4 blend → shrink toward 0.5 on disagreement / short text → gates
                  │ ai_score, confidence
                  ▼
Labeler: ≥0.80 likely_ai · 0.36–0.79 uncertain · ≤0.35 likely_human → 1 of 3 label texts
                  │
     ┌────────────┼─────────────────┐
     ▼            ▼                 ▼
SQLite content  Audit log JSONL   JSON response
(status)        ("submission")    {content_id, attribution, confidence, label, signals}

POST /appeal {content_id, creator_reasoning}
   → rate limiter (5/hour) → look up content (404/403/409)
   → SQLite status = under_review → audit log "appeal" entry (original decision + reasoning)
   → {appeal_id, status: "under_review"}
```

A submission passes the rate limiter and validation. The same raw text then goes to two
independent signals: an LLM that judges meaning and voice, and a stylometric analyzer that
measures structure. The scorer blends the two into an `ai_score` (0 = human, 0.5 = no idea,
1 = AI), pulls it toward 0.5 when the signals disagree or the text is short, and applies
asymmetric thresholds. The labeler picks one of three fixed labels. The decision is saved to
SQLite (current state), appended to the JSONL audit log (history), and returned with a
`content_id`. An appeal uses that `content_id` to flip the status to `under_review` and logs the
creator's reasoning next to the original scores for a human reviewer. The full diagram with
labeled arrows is in [`planning.md` → Architecture](planning.md#architecture).

| File | Responsibility |
|---|---|
| `app.py` | Flask routes, rate limiting, validation, pipeline orchestration |
| `signals.py` | `llm_signal()` and `stylometric_signal()` |
| `scoring.py` | `combine()`: blend, shrinkage, thresholds, gates; the three label texts |
| `storage.py` | SQLite content store + append-only JSONL audit log |
| `config.py` | Model, file paths, rate limits, every threshold and weight |
| `evidence.py` | Re-runs the test inputs, an appeal, and the rate-limit burst against the real API and writes the results into this README |

## Detection signals

### Signal 1: LLM judge (Groq, `openai/gpt-oss-120b`)

- **What it measures:** a holistic read of meaning and voice. The prompt lists AI tells (generic
  balanced claims, stock transitions like "Furthermore", uniform polish, abstraction instead of
  concrete detail) and human tells (specific idiosyncratic details, opinions with stakes, uneven
  rhythm, imperfections). It returns `{"ai_likelihood": 0–1, "indicators": [...], "reasoning"}`
  in JSON mode at temperature 0.
- **Why I chose it:** it's the only signal that can tell *what* is being said. "My grandmother's
  kitchen smelled like burnt cardamom" and "Family traditions play a crucial role in shaping
  identity" can have identical sentence statistics, but only one reads like a person.
- **Calibration:** the prompt tells the model to reserve values above 0.85 or below 0.15 for
  clear cases, to stay between 0.35 and 0.65 when the evidence is mixed or the text is short,
  and that formal writing is *not* evidence of AI by itself.
- **What it misses:** AI text prompted to "write casually with typos"; formal human writing
  (academic, legal, non-native English writers using a formal register) that looks like LLM
  output on the surface; and drift when the model version changes. It's also an LLM grading
  LLMs, so it shares their blind spots.
- **If it fails:** an API error or unparseable output marks the signal `unavailable`. The system
  keeps working on stylometry alone with extra shrinkage, and **can't** label anything AI.
- **Model note:** the course recommends `meta-llama/llama-4-scout-17b-16e-instruct`, which Groq
  has retired. The default is `openai/gpt-oss-120b`, the same replacement the course's Lab 4
  repo adopted. Override it with `GROQ_MODEL` in `.env`.

### Signal 2: Stylometric heuristics (pure Python)

Four sub-metrics, each mapped to 0–1 (1 = AI-like) and averaged with weights:

| Sub-metric | Measures | Why it differs | Weight |
|---|---|---|---|
| Burstiness | Coefficient of variation of sentence lengths (needs ≥ 3 sentences) | AI writes evenly sized sentences; people vary them | 0.30 |
| Stock-phrase density | Matches per 100 words against ~45 phrases LLMs overuse ("it is important to note", "furthermore", "stakeholders", "delve", "paradigm shift", ...) | These phrases are LLM habits | 0.30 |
| Informality | Lowercase sentence starts, lowercase "i", contractions, slang, ALL-CAPS emphasis, "!!"/"..." per 100 words | Casual human writing is full of these; AI output rarely is | 0.20 |
| Average word length | Characters per word | AI favors longer, Latinate words | 0.20 |

- **Why I chose it:** it measures structure, not meaning, so it fails in *different* situations
  than the LLM. That independence is what makes two signals more informative than one. It's also
  deterministic, free, and explainable: the response shows exactly which phrases were found.
- **Why not type-token ratio:** TTR falls as text gets longer, so across 50- vs. 500-word
  submissions it mostly measures length. I left it out on purpose.
- **What it misses:** formal human prose scores AI-like (long words, no casual markers, even
  sentences). Poetry and lyrics break sentence-based metrics, because line breaks count as
  sentence boundaries and refrains flatten burstiness. AI told to "write casually" adds exactly
  the markers this signal rewards. The phrase list is English-only and goes stale as models
  change their habits.

## Confidence scoring

### How the signals combine

```
raw         = 0.6 × llm_score + 0.4 × stylometric_score
ai_score    = 0.5 + (raw − 0.5) × (1 − 0.5 × |llm_score − stylometric_score|)
if words < 40:      ai_score = 0.5 + (ai_score − 0.5) × 0.85
if LLM unavailable: ai_score = 0.5 + (stylometric_score − 0.5) × 0.6
confidence  = max(ai_score, 1 − ai_score)
```

- **`ai_score`** is one scale: **0.5 means "a coin flip"**, 0 is confidently human, 1 is
  confidently AI.
- **`confidence`** is how sure the system is of the attribution it returned (0.5–1.0).
- **Disagreement is uncertainty.** If one signal says 0.9 and the other says 0.3, the honest
  answer is "we don't know", so the score is pulled toward 0.5 in proportion to the gap.
- **Asymmetric thresholds.** `likely_ai` needs `ai_score ≥ 0.80`, but `likely_human` only needs
  `≤ 0.35`. A false "AI" label harms a real person, while a missed AI text costs much less, so the
  bar for accusing is higher.
- **Gates.** `likely_ai` also requires the LLM signal to be available, each signal to lean AI on
  its own (LLM ≥ 0.65, stylometry ≥ 0.55), and ≥ 40 words. `likely_human` requires ≥ 25 words.
  When a gate blocks a label, the score is clamped into the uncertain band and `gate_note` says
  why, so the number and the label never contradict each other.

### How I validated that the scores are meaningful

1. **The four course test inputs** (clearly AI, clearly human, formal human, lightly edited AI),
   with both signal scores printed separately. Results are in the evidence section below.
2. **A sweep over LLM scores (0.05 → 0.95)** against each input's real stylometry score. This
   showed the clearly-AI sample only becomes `likely_ai` when the LLM is also fairly sure
   (≥ ~0.77). It also showed the two borderline inputs **never** get `likely_ai`, even when the
   LLM says 0.95, because stylometry disagrees. That's the false-positive protection working.
   The sweep is also how I found the short-text over-penalty (see Spec reflection).
3. **Automated property tests** (`tests/test_app.py`, 11 tests): all three labels are reachable;
   high- and low-confidence inputs differ by more than 0.25; every `likely_ai` result has both
   signals above their bars; the label always matches the score; an unavailable LLM can never
   produce an AI label.

### What the real run showed

- **The clear cases separate cleanly.** Clearly AI scored `ai_score` 0.90 (both signals ≥ 0.89),
  and clearly human scored 0.11 (both signals ≤ 0.12). Both got definite labels with ~0.90
  confidence, so the scale isn't stuck in the middle.
- **The two-signal design prevented a false positive.** On the *human-written* formal economics
  paragraph, the LLM judge said **0.88**, which is confidently AI, even though its prompt says
  formal writing isn't evidence of AI on its own. On its own that would have earned an AI label.
  Stylometry only scored it 0.57, so the disagreement pulled the combined score down to 0.72,
  below the 0.80 AI threshold, and the label came out "Origin unclear". This is the
  false-positive scenario from `planning.md` §4, now observed with real scores.
- **The LLM was fooled by light human-style editing.** The lightly edited AI paragraph got only
  0.28 from the LLM: it read "I've" and the em-dash as human voice. Stylometry (0.43) kept the
  result at "uncertain" rather than "likely human". That's a false negative, the cheaper kind of
  error, and arguably the right answer for mixed authorship.
- **Confidence tracks real uncertainty.** The two definite labels sit at ~0.90 confidence and
  the two borderline cases at 0.63–0.72. Those are different labels, not just different numbers.
- **The signals fail in different places,** which is the reason to have two. The LLM erred on
  formal human writing (too high) and on edited AI (too low). Stylometry was moderate on both.
  Neither signal alone would have produced the right labels on all four inputs.

## Transparency labels

The exact text readers see:

| Variant | When | Exact label text |
|---|---|---|
| **High-confidence AI** | `ai_score ≥ 0.80` and all gates pass | "🤖 Likely AI-generated. Our automated checks found strong signs that this text was written with AI. Automated detection can be wrong, and the creator can appeal this label." |
| **High-confidence human** | `ai_score ≤ 0.35` and ≥ 25 words | "✍️ Likely human-written. Our automated checks found writing patterns typical of a person rather than AI. This is an automated assessment, not a guarantee." |
| **Uncertain** | everything else | "❔ Origin unclear. Our automated checks couldn't confidently tell whether this was written by a person or with AI. Short, formal, or edited writing often gets this result, so please don't treat it as a judgment either way." |

Design choices:
- **No raw percentage in the reader-facing label.** "87% AI" invites over-trust and makes a
  0.81 look different from a 0.84 when the system can't actually tell them apart. The wording
  carries the confidence ("strong signs" vs. "couldn't confidently tell"). The API still returns
  `confidence` for a platform "details" view.
- **Every label says it's automated.**
- **The uncertain label explicitly says not to treat it as a judgment**, because readers tend to
  read "unclear" as "probably AI".
- **Only the AI label mentions appeals**, since it's the only one that can harm the creator.

## Appeals

- `POST /appeal` takes `content_id` and `creator_reasoning` (1–2,000 chars). If `creator_id` is
  included it must match the original submitter (`403` otherwise). In production, identity would
  come from the logged-in session instead.
- The handler sets the content's status from `classified` to `under_review` in SQLite. It then
  appends an `appeal` audit entry holding the **original decision** (attribution, confidence,
  `ai_score`, both signal scores, original timestamp) **and** the creator's reasoning, and
  returns a confirmation. A second appeal on the same item returns `409`, which keeps the queue
  from filling with duplicates. There's no automated re-classification.
- `GET /appeals` is the reviewer's queue, oldest first. Each item shows the label, `ai_score`,
  both signal scores, the LLM's indicators, the stylometry metrics (including which stock
  phrases matched), the gate note, a text excerpt, and the creator's reasoning. Seeing the
  per-signal scores lets a reviewer spot "stylometry alone drove this", which is the most likely
  false-positive pattern.

## Rate limiting

| Endpoint | Limit (per client IP) | Reasoning |
|---|---|---|
| `POST /submit` | **10 per minute** | A writer posts their own work a few times a day. Even uploading a backlog (a chapbook's worth of poems) rarely needs more than 10 a minute. Every submission costs one Groq call, so this also keeps one script from burning the free-tier API quota that every user shares. |
| `POST /submit` | **100 per day** | Leaves room for a very heavy legitimate day, or a small workshop sharing one network, while capping bulk flooding or using the endpoint as a free AI detector at scale. |
| `POST /appeal` | **5 per hour** | Appeals go to human reviewers, whose time is the scarcest resource. A real creator rarely contests more than one or two labels at once. |

Implemented with Flask-Limiter (`storage_uri="memory://"`), configured in `config.py`.
Exceeding a limit returns `429` with `{"error": "rate_limited", ...}`. Production would use Redis
so limits hold across multiple server processes, and would key on the authenticated user as well
as the IP, since an IP limit is unfair to people on a shared network. The actual 200 → 429 output
is in the evidence section above.

## Audit log

Append-only JSONL at [`logs/audit_log.jsonl`](logs/audit_log.jsonl), one JSON object per line,
also served by `GET /log`. Each `submission` entry records `timestamp`, `content_id`,
`creator_id`, `attribution`, `confidence`, `ai_score`, `llm_score`, `llm_status`,
`stylometric_score`, `signals_used`, `gate_note`, `label_variant`, `status`, `appeal_filed`,
`word_count`, a 200-character `text_preview`, and `model`. Each `appeal` entry records the
appeal reasoning together with the original decision and scores, so a single line tells the
whole story. Current status lives in SQLite (it changes), while history lives in the log (it
never does).

The sample entries are in the evidence section above.

## Known limitations

- **Formal human writing is the most likely misclassification.** Academic prose, legal or
  technical writing, and writing by non-native English speakers who learned a formal register
  all score AI-like on stylometry: long words, no contractions, even sentences, and often
  "furthermore"/"moreover", which are on the stock-phrase list. The real run confirmed the LLM
  shares this bias: it scored the course's human-written economics paragraph 0.88. Only the
  stylometry disagreement kept that out of the AI label. A formal paragraph that *also* uses
  several stock phrases would push stylometry above 0.55, and then both signals would agree on a
  wrong answer. That's the case the appeal path exists for.
- **Poetry and song lyrics.** Line breaks are treated as sentence boundaries, so a poem with a
  repeated refrain has artificially uniform "sentence" lengths (AI-like burstiness), while simple
  vocabulary makes it look human-like on word length. The stylometry score for poetry is mostly
  noise.
- **AI text told to sound casual** ("lowercase, slang, a typo or two") defeats stylometry by
  design, and the real run showed the LLM is also easily swayed by surface voice: one "I've" and
  an em-dash dropped the edited-AI sample to 0.28. Humanized AI text will usually come out
  "uncertain" or even "likely human" (a false negative, accepted because of the false-positive
  asymmetry).
- **Short texts (< 40 words) can never be labeled AI**, and under 25 words can't be labeled
  human. Captions and short poems get "Origin unclear" almost by default.
- **Mixed authorship isn't modeled.** A human-edited AI draft or an AI-polished human draft gets
  one score for the whole text.
- **Not production-hardened:** no authentication (`creator_id` is self-reported), in-memory
  rate limits that reset on restart, and the audit log stores a 200-character preview of each
  submission, which would need a retention policy in production.

## Spec reflection

**How the spec helped:** writing the asymmetric thresholds and the gate rules in `planning.md`
before coding (`likely_ai` only at ≥ 0.80, only if both signals lean AI, only at ≥ 40 words)
turned "be careful about false positives" into checkable rules. That made it possible to write
property tests ("every AI label has both signals above their bars", "the label never
contradicts the score") instead of eyeballing outputs. Having the three label texts fixed in the
spec also meant the code just copied them, with nothing to reinterpret.

**Where the implementation diverged and why:**
1. **Short-text cutoff: 60 → 40 words.** The plan shrank scores toward 0.5 for texts under 60
   words. Testing showed every course sample is 39–55 words, and that shrink stacked with the
   disagreement shrink, so the clearly-AI paragraph could only be labeled AI if the LLM was
   ≥ 0.85 sure. The 40-word AI gate already protects short texts, so I lowered the cutoff to 40.
2. **The per-signal gates turned out to be redundant with the disagreement shrink.** At
   0.6/0.4 weights, the blend can't reach 0.80 unless both signals are already high (LLM 1.0 +
   stylometry 0.50 only gives 0.72). I kept the gates as a backstop for future weight changes
   and test the property directly.
3. **Model:** the spec's Llama 4 Scout model is retired on Groq, so the default is
   `openai/gpt-oss-120b`.

All three are recorded in [`planning.md` → Changes during implementation](planning.md#changes-during-implementation).
